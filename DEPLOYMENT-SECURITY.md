# ACE website deployment and backend security plan

This document records the production setup. The secure Node.js authentication and content API live in `backend/`. Google Sheets and Drive integration remains a later phase.

## Hosting split

- Vercel hosts only the public files from `frontend/`.
- Render hosts the private Node.js admin API from `backend/`.
- Google Sheets will store structured website content after that integration is added.
- Google Drive will store uploaded images and applicant files after that integration is added.
- The browser never receives Render secrets, Google service account credentials, password hashes, or session-signing secrets.

## Render environment variables

The root `render.yaml` declares the variable names but contains no secret values. Enter private values in the Render dashboard during deployment:

- `ADMIN_EMAIL`: the initial admin email address.
- `ADMIN_PASSWORD_HASH`: the salted scrypt hash produced by `npm run hash-password` inside `backend/`, never a plain password.
- `SESSION_SECRET`: generated by Render and used to sign secure sessions.
- `FRONTEND_ORIGIN`: the exact Vercel production URL, such as `https://www.example.com`.
The Google variables are not declared in `render.yaml` yet because the integration does not exist. When it is built, add `GOOGLE_SERVICE_ACCOUNT_JSON`, `GOOGLE_SHEETS_ID`, and `GOOGLE_DRIVE_FOLDER_ID` to Render only.

Do not prefix any private variable with `VITE_`, `NEXT_PUBLIC_`, or another public-build prefix. Do not commit `.env` files.

## Authentication requirements

The production login is handled by the Render backend, not JavaScript stored in the browser.

- Accept login only over HTTPS.
- Compare the submitted password against `ADMIN_PASSWORD_HASH` on the server.
- Return an `HttpOnly` and `Secure` session cookie. The initial separate Vercel and Render domains require `SameSite=None`; CSRF protection and exact-origin CORS remain mandatory.
- Create a new signed session after login and expire it after the configured lifetime.
- Apply login rate limits and temporary lockouts.
- Require CSRF protection for every add, edit, delete, upload, and logout request.
- Never return password hashes, secrets, or Google credentials to Vercel or the browser.
- Protect all admin and content-management API routes with server-side authorization.
- Add an audit log before multiple administrators or sensitive applicant workflows are enabled. Never log passwords, cookies, applicant data, or access tokens.

The hidden ten-click footer shortcut is only a convenience. It is not a security control. The backend must reject every unauthenticated admin request even when somebody knows the login URL.

The current `vercel.json` temporarily redirects `/login`, `/login.html`, `/admin`, and `/admin.html` to the homepage. Remove those redirects after the Render URL is added to `frontend/config.js` and authentication is verified.

## API requirements

- Vercel may contain only the public Render API base URL.
- Render must allow CORS only from the exact `FRONTEND_ORIGIN`.
- Use JSON body-size limits and validate every field on the server.
- Allow image and CV uploads only after checking file type, file signature, and maximum size.
- Generate file names on the server. Never trust a user-supplied path or file name.
- Store applicant CVs in a private Drive folder and restrict spreadsheet access to authorized staff.
- Do not place private client, applicant, or admin data in browser storage.

## Email pathways

- `info@ace-outsourcing.com` is for prospective clients, service enquiries, and business partnerships.
- `hr@ace-outsourcing.com` is for careers, applicants, CV submissions, and recruitment questions.
- The contact page is the client pathway.
- The careers page is the applicant pathway.

## Before production launch

1. Deploy the Render backend and verify `/health`.
2. Add its URL to `frontend/config.js`, remove the temporary Vercel admin redirects, and push the changes.
3. Test login throttling, session expiry, CSRF protection, and access control.
4. Connect Google Sheets and Drive using backend-only credentials.
5. Add a private admin-user store if more than one administrator is required.
6. Rotate all deployment secrets after initial testing.

Until Google Sheets is connected, Render stores edited content on its local filesystem. That filesystem is ephemeral on the free service, so redeployments can restore the bundled defaults. Do not treat content edits as durable until Google Sheets or another persistent store is connected.
